Step 5: Next.js — Same React, Better Structure

What is Next.js?

Next.js is a React framework. It's the same React you learned (useState, useEffect, props), but Next.js handles the boring stuff:

  • Routing: File names = URL paths (no manual router setup)
  • Build: Optimized bundles for production
  • Server side: Optional server-side rendering, API routes
  • Dev server: Fast reload as you edit

You still write React components. Next.js just gives you structure and tools.

Comparison: Raw React vs Next.js

Raw React (what you made)

You did:

  • Write HTML file with script tags
  • Import React from CDN
  • Write components inline
  • Manual routing (onClick handlers)
  • No built-in API support

Good for: Learning, prototypes, simple sites

Next.js (what you build with)

Next.js does:

  • File-based routing
  • Automatic imports
  • Hot reload (instant feedback)
  • Built-in API routes
  • Built-in optimization (images, code splitting)

Good for: Real projects, teams, production

File-Based Routing (The Magic)

In Next.js, your file structure IS your routing:

app/
├── page.tsx (route: /)
├── about
│ └── page.tsx (route: /about)
├── blog
│ ├── page.tsx (route: /blog)
│ └── [id]
│ └── page.tsx (route: /blog/:id)
└── api
└── hello
└── route.ts (API route: /api/hello)

No router config needed! Create a file, the route exists.

Minimal Hello World: Next.js vs Raw React

Raw React (step1.html):

<!doctype html>
<html>
  <script src="https://unpkg.com/react@18/..."></script>
  <div id="root"></div>
  <script type="text/babel">
    function App() {
      return <h1>Hello World</h1>
    }
    ReactDOM.createRoot(document.getElementById("root"))
      .render(<App />)
  </script>
</html>

Next.js (app/page.tsx):

export default function Home() {
  return <h1>Hello World</h1>
}

That's it! No imports, no root div, no ReactDOM.createRoot. Next.js handles it.

The Same React Concepts

useState works the same:

'use client'; // Tell Next.js this is a client component

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </>
  );
}

useEffect works the same:

'use client';

import { useState, useEffect } from 'react';

export default function DataFetcher() {
  const [data, setData] = useState(null);

  useEffect(() => {
    // Fetch from /api/hello
    fetch('/api/hello')
      .then(res => res.json())
      .then(data => setData(data));
  }, []);

  return <div>{data?.message}</div>
}

Everything is still React. Next.js just manages the structure.

API Routes (Backend in the Same Project)

Create app/api/hello/route.ts:

export async function GET() {
  return Response.json({ message: 'Hello from API!' });
}

Now fetch('/api/hello') calls your backend. No separate server needed.

Client vs Server (New Concept)

In Next.js, React components can run on the server or client:

'use client'

Browser only (interactive)

  • useState, useEffect
  • onClick handlers
  • Browser APIs
  • This is what you've been learning

No directive (Server)

Runs on server (data fetching)

  • Direct DB access
  • No useState (no state)
  • Can await database calls
  • Advanced topic—learn later
