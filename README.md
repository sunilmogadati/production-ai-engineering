# Production AI Engineering

AI engineering taught from the production side — the through-line is judgment:
**Problem → pattern → architecture → the decision you'd defend in production.**

You'll build the ML foundations, then the AI techniques on top, then learn to ship and run any of it —
and finish with one real project that's genuinely yours.

## Layout

```
study-docs/     intuition-first study docs (plain English first, then the math)
  ML_Study_01_Intro_and_Linear_Regression.md / .html
  ML_Study_Figures/
  render.py     python3 render.py [doc.md]  → self-contained HTML
notebooks/      World_Bank_Data_Foundations.ipynb  (real World Bank data via wbgapi)
hands-on/       the incremental lab:
                  FastAPI     main0 → main4 → main → main_ai,  serve_step1 → serve
                  ML algos    hello_* → ai0* → ml01(gen) → ml06 → ml09/10 save+load → ml11 prospect
                  Claude API  prompt01 → prompt05
                  use-case    a call-center lead-scoring app on SYNTHETIC data
```

## Getting started

```bash
cd hands-on
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
./VERIFY_SETUP.sh
python3 ml01_generate_synthetic_data.py    # builds data/leads.csv (synthetic, not in git)
```

Then read `hands-on/START_HERE.md`.

## Reading a study doc

The `.html` files are self-contained — open one in a browser and every diagram and equation renders.
To rebuild after editing the markdown:

```bash
cd study-docs && python3 render.py
```

Requires `markdown` (`pip install markdown`).

## Notes

- **Data is synthetic or open.** `data/leads.csv` is generated by `ml01` — no real customer data anywhere.
  `.gitignore` blocks `*.csv` / `*.xlsx` by default; that friction is intentional.
- Model files and virtualenvs aren't committed — rebuild them locally with the steps above.
